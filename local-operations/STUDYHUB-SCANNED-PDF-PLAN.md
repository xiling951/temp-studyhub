# StudyHub 扫描教材图文解析修改方案

适用环境：本机 StudyHub 3.3.0、DSH Desktop 0.11.1，以及已核对的 DSH 0.2.0-rc.2 接口包。本文是实施方案，尚未修改应用。目标是再次导入扫描 PDF 后，获得可回溯原页的图文教材，并让依赖图片的学习与出题流程有实际图像依据。

审查修订：2026-10-09，第二版。原方案方向可行，但缺少若干关键接口与兼容约束，不能认定完全适配或无回归。以下第 9 节为实施的强制边界；第三方接口、桌面运行和旧功能回归仍须在实施后验证。交接与分步任务见 `STUDYHUB-SCANNED-PDF-HANDOFF.md`。

## 已确认的现状

- 普通 PDF 文字提取：8 MiB、200 页、60 万字符；扫描页通常没有可提取文字。
- PDF 转换上传通道已经允许最大 800 MiB，并支持分段、重试和缓存；不需要简单地把普通提取上限改到 800 MiB。
- 原文件保存、补全原文件和部分读取流程共用 40 MiB 上限。转换资料导入时没有自动绑定原 PDF。
- 本地 MinerU 当前通过分页 Markdown 转成 content_list；这一过程中已经损失部分结构。转换资料导入继续把图片简化成图注，Markdown 图片引用被清除。
- 模型调用准备层会移除嵌入的本地图片数据。保存一张图片或在提示词里写一个文件路径，并不能让模型看到图。
- 发布包只有编译后的前端和 prepare 脚本。正式实施应取得与 3.3.0 匹配的源代码，从源码构建定制发布包，不直接修改编译后的 client 分块。

## 1. 导入入口与原始文件

在“添加资料”里提供“扫描教材：保留图文”解析方式。超过普通提取上限或检测到没有文字层时推荐此方式，混合文字和扫描页的文件也允许主动选择。

复用现有分块上传和后台任务。大文件以服务端文件路径或上传凭证传递，不把整本 PDF 放进一个 base64 请求。整本教材的原文件流式复制到学习库并校验 SHA-256。仅新建图文教材采用原 PDF 哈希作为身份依据；已有文档的 documentId、sourceId、revision 和引用不能重命名。补全旧资料时将原 PDF 哈希作为额外身份关联保存。

新增图文原 PDF 存储通道，初始上限沿用 800 MiB；旧的 ORIGINAL_MAX_BYTES、document.bytes 和 base64 附件 API 保持原契约。不能仅把共享 40 MiB 常量改大。新通道以小块读取、下载和备份；若宿主公开接口允许，再增加受同一鉴权约束的 HTTP Range 支持，否则以现有认证消息桥的有界分块操作实现。新增可携带大文件的压缩备份格式，同时保留旧 JSON 备份的导入与原有小文件导出。旧格式不能完整携带新附件时必须明确说明，不能返回看似完整的缺图备份。

原 PDF 默认保留一份；原页预览按需生成，避免额外永久保存几百张整页大图片。

## 2. 解析与图片保留

保留现有按页分段、取消、重试、失败拆段和已完成分段缓存机制。当前 PDF Job 仅明确声明取消与重试，不能将其描述为已支持暂停或自动恢复；如需暂停或重启恢复，必须另外实现并按实际能力声明。新增 MinerU 结果适配层，优先读取公开接口支持的结构化结果与资源包，保存页码、内容块类型、阅读顺序、区域坐标、文字、公式、表格及图注。实施前对本机 MinerU 4.0.11 的接口做小样例验证；不把内部缓存路径作为长期接口。

每个图片、图表或表格区域都有独立 assetId、页码、位置、资源哈希和来源。优先复用结果包中的原始图像资源；没有图片资源时，从保留的原 PDF 按坐标裁切。裁切留适量边距，并检查坐标单位、旋转和页面尺寸。公共图注和多子图通过 parent/child 关系关联，不能把每个检测框都当作独立图号。

公式同时保留 LaTeX、公式编号和原区域引用；表格同时保留 HTML/结构化内容和区域图片。纯图片页保留页面记录，不再作为没有文字的页面丢弃；空白页也保留原页编号。

新页记录采用内容块列表，兼容原有 source.text 字段。文字字段继续用于旧流程，图片放在独立附件中，不向文字字段塞入大型 base64。资产按库内资源 ID 读取，不直接使用转换结果中的任意文件路径。

分段结果先写暂存区，校验资源存在和页码覆盖后发布为文档版本；中断任务保留已完成分段。不能把只有文件名、却不存在的图片视为已保存。

## 3. 图像理解作为独立阶段

增加“关键图解释”阶段，接入配置好的视觉模型。接口需要支持真正的图像输入，并检查所选模型能力；文本模型不能代替。每次输入相关图、图注和相邻正文，必要时附原页。

解释保存为独立记录，包含图像引用、模型和提示词版本、识别出的标注/连接关系/曲线趋势、解释、看不清或待核对的部分。模型解释不能覆盖教材原文；更换模型或人工修正产生新版本。

图文提取默认独立于视觉模型完成。可在导入时选择“仅保存图文”或“同时解释关键图”。没有可用视觉模型或模型调用失败时，仍保留图文结果，明确显示“图像解释未完成”，并允许后续按章节补做。

对于电路图，应核对连线交点、连接点、端口名称、晶体管类型及上下标。模型自己声称有信心不等于验证通过，自动解释默认标记为待核对。

## 4. 阅读、检索与出题

阅读器新增“图文正文”和“原页对照”。显示正文、公式、表格、实际图片、图注和可折叠的模型解释；点击图或引用能定位到原 PDF 的对应页与区域。原 PDF 页码与教材印刷页码分别记录，避免二者混用。

检索索引收录正文、图注与图解，但命中结果必须带回 assetId、页码、区域和文档版本。重新导入后按版本更新索引，不能只索引说明文字而丢失图像关联。

新增带图的模型调用入口。出题规划、答案准备与独立审阅均取得所引用的实际图像；按章节和相关图选择输入，不能一次把全书图片都交给模型。图像输入走专门入口，保留旧文本入口的图片清理行为。

题目记录关联图片资源和引用；测验与闪卡页面能显示题目依赖的原图。若当前出题模型只支持文字，仅允许使用足以独立支撑问题的正文或已人工核对图解；需要读图才能回答的题不能自动发布。视觉模型不可用时清楚提示此限制。

## 5. 保存结果与导出结果

建议新增库内附件目录 `<当前学习库root>/attachments/textbooks/<原PDF哈希>/`。当前工作区默认 root 才是 `.dsh-study`，实现不得写死 D 盘或 `.dsh-study`。它是内部存储，图片说明和解析版本分别管理；原文件及相同图片按哈希复用。

用户点击“导出图文教材”后，输出一个文件夹或 ZIP，包含：

```text
教材名称/
  original.pdf             原始扫描 PDF，字节与导入文件一致
  index.html               按页浏览的图文阅读页，可对照原 PDF
  textbook.md              全文、公式、表格、图注及实际图片相对引用
  document.json            按页组织的内容块、顺序、坐标与资源关联
  manifest.json            文件哈希、页码覆盖、解析器/模型版本和状态
  quality-report.json      缺页、空白页、资源缺失及待核对项目
  figures/                 实际图片、曲线、表格等区域资源
  figure-notes.json        图像解释及核对状态；启用解释阶段时生成
```

此目录为建议输出格式，尚未生成。Markdown 必须与 figures 一起使用，单独复制 Markdown 不包含图片文件。主阅读页实际呈现公式和图片，而不是把全部 Markdown 放入纯文本预览。原 PDF 和导出资源由受控本地文件路径或应用文件服务访问。

## 6. 再次导入后的用户体验

1. 选择或拖入教材，选“扫描教材：保留图文”，可选同时解释关键图。
2. 依次显示“原文件已保存 → 分页解析 → 图表保存 → 完整性检查”；启用解释时另显示“图像解释”。
3. 完成后出现一本教材，章节可展开，每页显示其实际图文内容。原文件、图文、图像解释与核对分别显示状态。
4. 同一 PDF 再次导入复用原文件和已校验缓存，补缺失资产；解析器或配置更新时建立新解析版本。旧资料与已引用题目不被覆盖。
5. 无文字层不再导致页面消失：图片页仍可阅读，也可在有视觉模型时作为图像证据使用。
6. 失败或低质量结果显示具体页码和阶段，允许只重做这些页。

以本机《数字集成电路》为例，期望输出一份包含 572 个原页记录的文档及原 PDF。现有缓存标记了 691 个 image 块、155 个 chart 块、63 个 table 块；这些是检测区域数，不是已验证的独立图号数。最终图片文件数以合并、裁切和检查结果为准，不能提前承诺固定数量。

原 PDF 第 200 页应显示图 6.14、图 6.15 的两个子图以及图 6.16，同时保留相邻正文；启用解释后在这些图旁展示带来源的解释和待核对项，而不是仅显示图注。

解析完成状态应分别列出：原 PDF 保存状态、页码覆盖、文字/公式/表格提取、已保存图像、图像解释进度及待核对数量。页码齐全只说明所有页都有记录，不等于每一个内容块都识别正确。

## 7. 修改落点

- `lib/contexts/audio/convert.js`、`lib/audio-upload.js`：导入方式、解析模式参数，复用大文件上传。
- `lib/mineru-local.js`、`lib/mineru-job.js`、`lib/mineru-merge.js`：结构化结果和资源适配、分段合并、资源完成后再清理任务。
- `lib/converted-document.js`、`lib/contexts/materials/files.js`：图文内容块投影、纯图片页、资源引用。
- `lib/contexts/materials/operations.js`、`original-file.js` 及相关契约：绑定原 PDF、存储版本、流式读取/导出、元数据接口。
- 新增图像附件、图解任务、质量检查与导出模块，并适配资料持久化及备份。
- `lib/runtime/models.js`、模型网关、`lib/generation.js`、`lib/batch.js` 和检索扩展：带图输入、引用、审阅、资源返回。
- 对应前端源代码：导入选项、分阶段进度、图文阅读器、图解核对、带图题目、导出。

所有模块从匹配版本源码构建，在独立测试库验证后打包为可回退的定制版本，再替换当前安装。保留原版包和学习库备份。

## 8. 实施顺序和验收

第一阶段完成原 PDF 保留、结构化图文、纯图片页、图文阅读和导出；这是解决“图片丢失”的必要交付。第二阶段接视觉模型、图解与核对。第三阶段接带图检索、出题和审阅；只有完成第三阶段，才能说 StudyHub 出题也能直接依据图像。

先用原书第 200–206 页验收，再跑全书：

- 大文件走转换通道，原 PDF 保存后哈希相同，查看与下载无 40 MiB 拦截。
- 对照第 200 页检查全部电路图、子图、标注和图注；纯图片页保留，文字识别失败状态可见。
- 每个资源引用可读取，公式编号及表格原图可定位；跨段页码、坐标和子图关联正确。
- 全书覆盖 1–572 页，无重复页和缺页；检测漏块仍需原页抽查，不能由覆盖统计推断无漏图。
- 中断/重启恢复、缓存复用、重复导入、文档版本和旧引用保持有效。
- 没有视觉模型时能完成图文保存，界面不声称已理解图片。
- 用实际带图输入检查规划、答案和审阅链路，并验证题目界面的原图显示与原页引用。
- 导出后离开 StudyHub 仍能读取全文和图片；备份/恢复后资源与旧题引用完整。

完整性的承诺是：原始资料始终保留，已提取内容及关联资产可以核验，未完成或不确定的部分明确标记。自动识别和图像解释的百分之百正确不在承诺范围内。

## 9. 环境与功能兼容性审查后的强制约束

### 9.1 锁定源码与运行基线

从上游 `v3.3.0` 标签建立独立源码目录，记录完整提交号和依赖锁文件，再与本机发布包核对。不可直接在已安装 node_modules 或编译后的 client 文件上开发。当前本机 Node 为 24.13.0，StudyHub 要求 Node >=22.19 和 DSH >=0.2.0-rc.2 <0.3。

先在原始源码建立 lint、测试、构建、发布包检查和桌面 smoke 基线，将预先存在的失败与新增回归区分。发布包检查通过不等于真实 DSH 使用通过。桌面 profile 和独立 dsh-home 是两个不同环境，不能混用凭据、学习库和安装目标。

### 9.2 数据、身份与文字定位

第一阶段优先把可选图文扩展保存在 documents 的解析版本及库内资源清单中，所有 572 页都有页记录，但只有存在真实文字证据的页面进入旧文字选择、翻译与出题路径。纯图片页不能通过虚构“本页是图片”正文满足原文引用规则。

旧 source.text、ID、引用及字符偏移保持不变。图解、OCR 修正或新解析需要新版本，不得插入旧 text 或影响已保存的选区、批注、翻译和旧题。旧版本资源不能随当前版本切换被清理。新字段默认可选，缺失时按旧版行为处理。

不得随意提高全库 store.version：旧构建对高于 4 的版本拒绝读取。若必须进行破坏性格式升级，要先实现明确迁移、备份和回退工具；回退安装包不等于数据可回退。第一阶段应采用可选扩展，保留旧版读取文字的能力。

### 9.3 Context、操作与持久化注册

新材料操作必须在 materials 契约与 runtime/builtins 注册，声明读写集合、模型要求和跨域授权；新增集合同时注册 collections、defaults 和存储，不允许直接修改 study-workspace.json。

audio 当前仅通过获准的 materials 操作导入结果。新增图文提交操作需显式授权；generation 读取图片资源、library 导出/恢复新附件也需相应的命名端口和 grants。契约中不能透传任意绝对文件路径。

功能在仅启用 materials、关闭 audio、关闭 generation、没有视觉模型、未安装 retrieval，以及插件卸载/重载时均应降级明确，不引入反向依赖或重复注册。

### 9.4 原生模型、附件与任务

优先复用 DSH 的 ctx.llm、模型目录和附件服务。已检查的 DSH 接口中图像块为 `{type:'image', attachment: ImageAttachmentRef}`，不是把 DeepSeek 的 `image_url` 直接塞入 DSH 消息。先通过附件服务获取有效引用，再由 provider 适配器组装请求。不得读取凭据文件自行绕过 DSH 调用云端模型。

StudyHub 的直接模型调用目前构造单个 text 块，子任务模型网关也把提示拼成 text。需要新增明确的结构化内容入口，并同时处理 direct 与 subagent 路径、模型能力、图像预算与 offload；旧 complete(system,prompt) 保持兼容。被卸载为占位文字的图片不得声称已被模型看到。

新图解任务须通过现有 Job 定义、DSH executor、gateway、取消信号和用量统计执行。不能建立第二套任务表、偷偷新建 Agent 或无限轮询。只在确实实现后声明暂停、checkpoint recovery；没有活动 Agent/executor 时返回当前框架的不可执行状态。

### 9.5 大文件、事务与资源生命周期

800 MiB 是上传允许值，不能当作当前机器可高效处理的保证。现有部分 PDF 处理仍一次载入文件，需要测量峰值内存，并设置独立解析并发/页渲染预算；保持转换一次一份的默认行为，不抢占出题和录音资源。

落盘资产完成和校验后，再通过库事务引用不可变清单；事务失败留下的未引用文件可后续回收，已提交文档不能引用半成品。清理只回收不存在于任何文档版本、题目/草稿和活动任务中的资产。归档不等于删除。

缓存键包含原文件哈希、解析器版本、tier/模式、页范围、适配器及资源格式版本。旧文字缓存只能证明文字可复用，不能直接标为图文资源齐全。转换临时目录与永久教材目录严格分开。

### 9.6 图像证据与题目显示

现有题目发布验证依赖 sourceId + 原文 quote。不能关闭 quote-match 验证，不能把模型图解伪装成教材原文。第一阶段只支持有真实文字依据的旧式题目，图片作为可查看的关联材料。

第三阶段新增独立 visualCitations：至少包含文档版本、页码、assetId、资产哈希、区域引用和核对状态。普通 citations 继续走原规则，图像引用走独立校验器；同时有二者时分别检查。纯图片题只有该验证链实现后才能发布。图像存在和模型解释本身并不能证明答案正确。

题目资源字段须从生成输出到草稿、编辑、审阅、发布、JSON 导入/导出、公开题目 DTO、测验/闪卡/考试/口试和错题复习完整贯通。现有 publicCard 会省略新增 assets 字段；显示时只返回受控图像元数据，不能通过图解或答案字段提前泄露解答。

### 9.7 检索兼容

现有索引 hash 仅覆盖 source.text，normalizeHits 不保留 assetId、revision 或 bbox。不能假定仅修改检索扩展即可解决。优先在 StudyHub 侧通过 sourceId 解析当前版本的图片映射，以维持 mcp-local-rag 的现有工具契约。

如果收录图解，索引内容与变更 hash 要一起覆盖正文、选用图解版本和图文版本；新增索引 schema 要有重建标识。排除历史版本的默认搜索，旧题查证仍可读取历史证据。检索命中内容块只携带附近/被引用的图，不能把整页所有图或整个章节一次塞入模型。

### 9.8 发布、开关与回归

增加默认关闭的图文教材扩展开关，按文档选择解析方式。关闭开关或视觉模型失效时，普通 PDF、Word/PPT、Markdown/JSON、录音转写、旧题与 SM-2 维持原路径。Markdown 图像引用只在新图文包导入中解析，不解除通用清理器的文件访问限制。

回归需包含：课程总纲/归类、归档/恢复、引用与选区、翻译/批注、普通出题/补题/审阅/发布、带图题 DTO、闪卡/测验/考试/口试/错题、SM-2、录音导入/实时课堂、检索、备份恢复、插件独立加载及卸载、旧库读取和发布包安装。逐阶段验证必要变更；无需为纯文档修改新写测试。
