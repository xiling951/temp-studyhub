# 扫描教材方案审查与 DeepSeek V4.1 实施交接

审查日期：2026-10-09。对象：`STUDYHUB-SCANNED-PDF-PLAN.md`，现已修订为第二版。应用代码尚未修改。

后续已生成具体任务计划：`D:/studyhub/STUDYHUB-SCANNED-PDF-IMPLEMENTATION.md`。新会话实施时同时阅读该文件，按 T01–T12 执行；本文件保留审查证据和兼容约束。

## 审查结论

原方案的产品目标和整体方向可行，但不足以直接判定完全适配 DSH/StudyHub，也不能保证不会影响其他功能。按原方案一次性修改全链路存在高风险。第二版补齐了关键边界，适合作为分阶段开发规格；它仍需源码基线、接口验证、实际运行和回归测试，才能形成兼容性结论。

证据范围：本机发布包、桌面端安装的 StudyHub 3.3.0、运行中的 DSH Desktop 0.11.1、独立 DSH 0.2.0-rc.2 接口包、本机 Node 24.13.0、真实函数独立探针，以及官方 DeepSeek 文档。未验证桌面运行中 provider 的实时图像目录、附件服务调用、真实模型往返或本方案的运行性能。

## 主要问题及处理

### [P1] 大文件上限与读取/备份通道耦合

`lib/contexts/materials/operations.js` 的 `materials.document.bytes` 读取整份原文件并返回 base64；`original-file.js` 会收集整份文件到内存；`files.js` 的导出也以 base64 携带附件；`host.js` 对恢复请求设 64 MiB 上限。仅放大 ORIGINAL_MAX_BYTES 会使阅读、恢复和内存承载不相称。

处理：保留旧常量和旧 API 的小文件语义，新增大文件分块资源操作与压缩备份；只在宿主公开扩展能力验证后使用 HTTP Range。大文件存储上限不代表解析可全量载入内存。

### [P1] 原 PDF 哈希身份可能破坏旧引用

目前普通/转换文档身份与输入 bytes 和 format 关联；已经存在的 sourceId、materialRevision、选区和批注依赖旧记录。把所有文档重新命名成原 PDF 哈希会使旧引用失效。

处理：仅新图文文档使用新身份策略，旧文档额外关联原 PDF。所有旧 source.text 和 ID 不变，新 OCR 和图解采用新版本/侧挂记录。

### [P1] Context 与持久化权限没有覆盖新增操作

`runtime/domain-contracts.js` 声明 fields、reads、actionGrants 和写集合；`runtime/builtins.js` 从它们生成能力、集合和操作注册。audio 当前通过获准的 `materials.v1/document.import` 调用导入；新图文提交或资源读取不会自动拥有权限。

处理：明确归属 materials，逐项注册契约、读写范围、端口与授权。新增集合有显式注册；不得绕过 Store 或直接写全库文件。依赖可选插件时定义降级。

### [P1] 保存图片不等于模型收到图片

`runtime/models.js` 清理图片字节；`index.js/modelCompletion` 构造 text-only 用户消息；`jobs/gateway.js` 的子任务提示同样拼成 text。DSH 本身的接口包已有 image + ImageAttachmentRef 类型，但 StudyHub 的当前入口未贯通它。

处理：使用 DSH 附件服务和原生 image 块，扩展 direct/subagent 的显式结构化入口，保持旧 complete 接口。模型能力未知或 offload 后应报清楚，不能将占位路径当作视觉输入；仍由现有 gateway 记录请求、取消和用量。

### [P1] 图片引用与题目发布规则不兼容

`domain.js/validateDeck` 与 `quote-match.js` 对普通 citations 检查真实文字引用；纯图片没有可匹配的原文。另有 `publicCard` 固定投影，会省略提议新增的 assets。

真实函数探针：纯图片页的文字引用返回 `quote-not-found`；新增 assets 不出现在 publicCard 返回值中。

处理：不放松旧文字引用校验；后续新增 visualCitations 和独立校验，贯通题库、发布、练习页面和导出。第一阶段先不发布依赖纯图证据的题。

### [P1] 检索无法自动保存图片关联与图解版本

`retrieval-index.js` 仅根据 source.text 判断变化；`retrieval.js/normalizeHits` 只规范化文本、sourceId、页码、文档和分数。扩展包主要负责启动 mcp-local-rag，并不是完整的索引 schema 实现。

真实探针：assetId/revision/bbox 被规范化函数省略；正文不变、图解变化时计划新增索引项为 0。

处理：先在 StudyHub 侧由 sourceId 解析图像和版本映射；加入图解后同步修改索引正文、hash 和 schema 标识。保持旧工具接口，验证后再扩展外部服务。

### [P1] 新资源缺少明确生命周期和旧库回退策略

Store 的全库版本目前为 4，旧程序拒绝读更新版本。已有文档保留历史资料供旧题引用；只保存当前图片会导致旧题丢图。文件落盘与库事务也不是同一个操作。

处理：可选扩展优先，不无必要提高全库版本。先完成不可变资源和清单，再通过事务引用；只回收所有旧版本、题目和任务都没有引用的资产。旧版可读取文字不意味着旧版完整支持图文备份。

### [P2] 暂停能力被原方案写得过强

PDF Job 仅显式声明 cancel/retry；注册器默认 pauseMode 为 unsupported、recoveryMode 为 none。转换缓存复用不等于原生暂停和自动恢复任务。

处理：方案已修订为取消、重试与已完成分段复用；新能力另外开发并如实声明，接入 Job 注册、生命周期和宿主 executor。

### [P2] 现有图片功能与源码分发边界

StudyHub 已有受限制的嵌入位图 Markdown 校验（单图 2 MiB），并非完全没有任何图片显示能力。但它不等于新教材的多图片资源 ID、引用和模型输入支持。不可为兼容教材而取消通用图片/HTML清理规则。

本地是 npm 发布包，不含完整 UI 源码和测试。上游有 v3.3.0 标签。应取得该标签、记录完整 commit 并核对，不能在 node_modules 上开发或用最新 main 替换基线。

## DeepSeek V4.1 是否适合

如果指 DeepSeek V4.1 Flash：可以作为代码实施代理，配备文件访问、终端、匹配源码、依赖和测试后执行下面的里程碑。这是任务与环境适配判断，不是本项目上的模型成功率测量；模型名称本身不能保证无回归。

官方发布说明确认 V4.1 Flash 支持视觉，当前 API 模型名为 `deepseek-flash`。它也可以作为第二阶段的图解候选模型，但必须从 DSH 的实际 provider/model 目录选取并验证该路由的图像能力，不可盲目硬编码或把官方模型名当作当前 profile 中一定存在的路由。

官方视觉文档：Chat Completions 的图片放用户 content 中，支持 base64 图片、可访问 URL 或 Files API；当前请求体上限 48 MiB，直接单图上限 32 MiB。图像会被缩放，因此电路细节采用局部图 + 上下文，不能用整页缩略图代替。DSH 和本地附件通道可能有更严格预算，取实际链路最小值。不得用大量图片请求或百万 token 上下文替代有界解析。

## 可直接交给实施代理的任务

请阅读本文件和修订方案，基于 StudyHub v3.3.0 实施扫描教材图文保留功能，适配本机 DSH Desktop 0.11.1/DSH 0.2 接口。按以下顺序交付，前一里程碑通过相关验证后才进入下一项。每项保留可单独审查的变更和实际测试记录。

### M0：准备与证据

- 从 v3.3.0 取得独立源码，记录完整提交和依赖，核对与已安装包的关键文件一致。先读取该源码的 AGENTS.md 或项目规则。
- 建立原版 lint、测试、build、release:check 和 DSH smoke 基线；基线问题单独记录。
- 验证 MinerU 4.0.11 的公开结构化/资源导出接口与页码坐标语义。临时读取内部缓存只能用作迁移或对照，不作为长期协议。
- 核对真实 DSH 模型目录与附件服务能力、认证消息桥的分块限制和可用文件服务接口；只读取必要配置，不打印或复制密钥。
- 写出具体接口 DTO、资源清单 schema、依赖图和功能开关。默认关闭，新文件操作均限定学习库和文档版本。

### M1：保存与导出

- 复用 PDF 上传/转换通道，保留原 PDF，保存结构化文本、公式、表格和图片资源；纯图片/空白页保留在页清单中。
- 保持旧 ID/text/offset，新增可选版本扩展。处理图片哈希、子图、坐标和引用范围。
- 注册材料侧提交与资源操作；完整处理原文件证明、事务、任务临时文件清理和历史资源保留。
- 新增资源分块读/导出，不改大旧 base64 API，不自动改写旧备份格式；导出失败不得遗漏资产。
- 在独立测试库用 p200–206 样例验证；原文件哈希一致，图 6.14–6.16 保留，引用能定位；旧普通文档/旧 JSON 备份仍可读。

### M2：阅读器与大文件备份

- 从 ui 源码增加图文视图、原页对照、图片放大、页码及分阶段状态；表格和公式实际渲染。
- 先用现有认证桥提供按页/按块服务；宿主支持时才接 HTTP Range，不私自开未鉴权的独立服务。
- 新增附件压缩备份和有界导入/恢复，保留旧 API。包含课程、题库、SM-2、现有附件和历史版本；导出教材与导出整库是两个明确操作。
- 验证无模型、可选插件缺失、插件重载、取消重试、重复导入及备份恢复。测量 188.9 MiB 教材的峰值内存和磁盘使用，再跑 572 页，结果含质量报告。
- 完成 M2 即可交付“重新导入后能读到图文教材”；此时不能宣称可以自动依据纯图片出题。

### M3：图解任务

- 新增 DSH 原生结构化图像入口、有效附件引用和模型能力检查；保留旧文本 complete 接口与清理器。
- 图解通过现有 Jobs/gateway 执行，声明实有 cancel/retry/recovery 能力，计量归入既有账本一次。
- 输出独立、版本化的图解记录及核对状态，不能写入旧原文。输入图片含局部图及相邻文字，模型不确定就标记。
- 用一张真实电路图验证模型实际收到图片，缺视觉能力/offloaded 图片明确降级。检查取消、超时、429 和模型切换，不形成第二套调度器。

### M4：图像证据、带图题与检索

- 新增 visualCitations 校验，普通 citations 继续原规则；同时验证资源所属文档/版本/区域与实际哈希。
- 贯通规划、答案准备、生成、审阅、编辑、发布、DTO、复习/考试/口试/错题和 JSON 导入/导出。作答前只显示必要图片，不泄露答案/图解。
- 检索通过 sourceId 回填资源；图解变化触发索引更新，默认检索排除旧版本，缺外部扩展时旧流程继续使用。
- 所有只读图题在独立图像证据校验与真实审阅链完成前仅留草稿；不能关闭引用检查或用 importedFromJson 绕过发布检查。

### M5：回归与交付

- 运行与变更有关的测试和项目规定检查，覆盖修订方案第 9.8 节；完成真实桌面端与独立 profile smoke，明确在哪个 profile 测试。
- 检查变更包内容、版本与安装路径，交付定制 tgz、校验值、方案、测试结果、已知限制和回退步骤。
- 本请求的范围是方案审查和交接，不授权本次审查直接替换用户已安装插件或迁移正式学习库。实施代理接到新的实施任务时按其实际授权范围推进；在独立源码与测试库开发，先让可安装产物和测试证据可审查。

## 禁止的捷径

- 只改大小常量；把 800 MiB PDF 或几百张图片塞进一条 base64 请求。
- 重命名旧 source/document IDs、重排旧正文字符、将自动图解标为教材原文。
- 直接操作宿主私有 Agent/控制器、绕过 DSH provider 自行读取密钥、第二套后台任务/用量账本。
- 仅在 draft 保存图片字段，却不改 publicCard、引用验证和练习显示链。
- 仅改检索扩展却忽略 StudyHub 的索引 hash 与结果规范化。
- 宣称缓存命中等于资源齐全、页码齐全等于识别准确、tgz 检查通过等于桌面运行通过。
- 未回归就自动用新版包覆盖当前安装；用较新 main 替代明确版本的源码。

独立验证输出：`lab/import-probe/plan-compatibility-results.json`。它验证的是当前接口的限制，不是新方案的成功运行。
