日期：2026-10-11。源码基线：`179f68d0`；当前定制版本：`3.3.0-scanned.3`。工作区：`D:/studyhub`；实际源码仓库：`D:/studyhub/implementation/source`。

**本文件交付的是开发计划和预算估算。云端整书解析、新电子书阅读器、普通批量自动带图出题尚未实现，也没有执行 GPT-6 Luna 整书转换。** 以下 C01–C12 是新任务，不覆盖既有扫描教材 T01–T12 的历史记录。

## 1. 目标与产品流程

用户点击“导入资料”，选择 PDF 和 DSH 中已配置的视觉模型，开始后台解析。完成后点击“阅读”，可看接近原书的分页原貌，也可看适合屏幕的图文电子书；两种视图可对照，文字、图、表、公式与原页互相定位。资料可导出为含 HTML、Markdown 全文、结构化 JSON、真实图片和原 PDF 的资源包。使用原有“从资料出题”“创建题组”、练习、考试和复习入口时，图像证据贯通，题目仍经过独立审阅。

默认采用“云端识别 + 本地轻量处理”：本地仅保留原文件、检查页数、渲染/裁图、校验、排版、打包；不要求下载或运行新的重型 OCR/视觉模型。本地 MinerU 继续作为已有可选解析方式。

阅读目标分两部分：

- **分页原貌**：显示保存的原 PDF/原页，保留原书排版和图像，是对照的依据。
- **图文电子书**：正文段落、章节、公式、表格和原图重新排版，便于搜索、选区、批注和出题。它追求内容与结构忠实，不承诺字体、换行和每个像素与原书一致。

不把整页截图称为可搜索的电子书，也不把模型生成的摘要称为“MD 全文”。看不清的部分有原图与待核对标记。

- PyMuPDF 全书读取到的原生文字仅 1,079 字符；抽查前部和正文页均无文字层，末页有文字。不能用 PDF 原生文字提取完成全文。

- 当前图文版本有 572 页、1,321 个资产（包括原 PDF）；块分类含 691 个 image、155 个 chart、63 个 table、411 个 equation。这些是现有解析结果的计数，不是原书实际图表数量的人工真值。
- 当前块文字合计 595,111 字符，加入块分隔符后 601,785 字符；当前完整 manifest JSON 为 3,210,178 字符。这里只统计当前版本，未把两版 sources 重复相加，也不将字符数直接等同于 Token 数。
- 已目视检查 PDF 第 149 页（印刷页 131）的静态 CMOS 反相器、201 页（印刷页 183）的公式与跨页表格，以及 292 页。292 页本次原页目视为空白；后续不能把所有“无识别内容”页一律当成空白。

主要困难是中文密集小字、上下标、晶体管符号与连线、双栏/跨页顺序、表格续页，以及模型接口可能对整页图片再次缩小。更换模型可改善识别，但不会自动解决结构、对照、引用和题目质量。

## 4. DSH 模型与任务接入边界

所有云端推理复用 DSH 的模型目录、provider、凭据、原生附件和 Jobs/gateway。StudyHub 不新增密钥库，不直接读取用户密钥文件，不绕过宿主直接向模型厂商发请求。DSH 的模型配置可以指向云 API；“桌面端配置了模型”不等于必须本机运行模型权重。

新增“云端图文解析”选项，旧普通导入、转换资料和本地 MinerU 入口继续保持。解析模型与出题模型分别选择，预先展示真实 provider/model 身份；任务开始后固定绑定，模型切换生成新结果版本，不混用旧缓存。

C01 必须验证宿主实际支持的图片尺寸处理、detail、输出上限、JSON Schema、reasoning 参数、用量和计费数据，不把 OpenAI Responses 支持的参数假定为 DSH 已暴露的功能。转写请求使用最低可用推理档；Luna 优先验证 none，不继承当前会话的 high 配置。专业图解可另设推理档并分别记账。Structured Outputs 未透传时，使用现有 JSON 请求、严格本地校验与有界纠错，明确这是应用校验而非厂商强制 Schema。

默认以“本地分页渲染 → 原生图片附件 → 模型返回 JSON”接入，宿主支持图片便能开展，不依赖厂商 PDF 文件接口。OpenAI 官方说明 PDF 文件输入同时使用文字与页面图像，且每次请求全部文件合计限制为 50 MB；本书约 198 MB，不能一次原样上传完成转换。原生 PDF 输入只能作为能力验证后的可选分段路线。[文件输入说明](https://developers.openai.com/api/docs/guides/file-inputs)

本地渲染应有可检测的轻量运行环境：优先复用已安装 PyMuPDF；交付时明确检测/安装方法或提供合法可分发的轻量运行方案，不能默默依赖开发机 Python。PDF.js 已有渲染能力可评估复用。新增运行时分发须检查依赖许可证，不因“轻量”忽略包体和许可要求。

## 5. 分页识别与质量处理

1. **导入与准备**：沿用分块上传、原 PDF 流式保留和 SHA 校验，检查真实页数、尺寸、旋转、文字层和扫描分辨率。原书可先在导入预览中查看；尚未校验的解析结果不成为正式可引用资料。
2. **逐页结构识别**：每次先处理 1 页，输入清晰整页图，请模型忠实转写正文，返回块类型、阅读顺序、章节/印刷页码候选、坐标、图注和无法识别项。只允许转写与结构识别，不要求补全缺失文字或撰写知识解释。
3. **自适应局部重识别**：密集文字、公式、表格和复杂电路图拆成有重叠的局部图，保持字符有效像素。整页概览负责结构，局部图负责细节。缩放/切片策略依据实际 provider 的缩图行为确定，不能只增加提示词。每个请求满足现有 4 图/8 MiB 边界，必要时连续调用。
4. **坐标与裁图**：模型 bbox 先标为候选；检查边界、实际内容、图注匹配与漏裁，再从原 PDF/原扫描图裁出真实资产。保存 CropBox、旋转、缩放、去倾斜和切片偏移的映射，提供变换及逆变换；页面显示和模型坐标必须可回到同一原区域。图号和多子图采用父子关系。
5. **跨页整理**：以相邻页和章节骨架恢复段落、去除阅读视图中的重复页眉页脚、连接续表和正文引用。保留各页原始转写，跨页合并以显式映射记录，不能改变原书页号或让旧选区失效。目录、参考文献和练习区单独标注。
6. **图表与公式双重保留**：表格同时保留原区域图、结构化单元格及净化 HTML；公式保留原区域、LaTeX 和编号；电路图和曲线保留原像素，不用模型重画替换。无法可靠转写时显示原区域和“待核对”。
7. **质量检查**：校验块/页完整性、图片资源、正文引用、公式编号、表格行列以及已识别页与原页内容差异。模型置信度不是准确率；关键器件/连线/单位须实际图像复审，仍不确定就不进入自动出题证据。

默认并发 1–2 页；按限流、内存和附件大小实测调整。对 429、超时和短暂网络故障有界重试；格式截断先降低批量或分区，不无限重发整页；不支持图片、权限/认证失败等错误停下来保留检查点。没有视觉模型时可保留原书，不能声称云端解析完成。

## 6. 统一结构与资源包

扩展现有 visual manifest，不更换整个 Store。新格式采用显式 schemaVersion/能力声明，新增字段兼容旧读者；旧版本按既有结构读取。云端原始输出、规范化块、人工修正、阅读投影、图解分别保存，并记录出处与版本。

新增字段的具体名称在 C02 契约测试中冻结，至少包含：文档/版本/原 PDF 哈希；PDF 页号与印刷页号；原页面几何；块 ID、类型、顺序、正文、公式或表格；章节关系；图注/子图/正文引用；原区域与坐标变换；资产 ID/哈希；识别模型和配置指纹；待核对项与检查结果。

模型只返回内容 JSON。程序决定文件名、目录、资源引用和 HTML 模板，并校验实际资产；不把模型返回的路径、脚本、外链或“已保存文件”声明当成真实资源。

资源包在现有导出上增量扩展：

```text
book-package/
  manifest.json                # 格式版本、文件哈希、能力、来源和构建信息
  original.pdf                 # 不改写的原 PDF
  document.json                # 页/块/章/图/表/公式结构及区域映射
  textbook.md                 # 完整阅读正文，带真实图片、公式和原页锚点
  index.html                  # 章节电子书入口
  chapters/                   # 大书按章输出的 HTML
  figures/                    # 真实图、表、公式区域资产
  viewer/                     # 本地受信任 CSS/JS、公式字体、PDF.js 资源
  mappings.json               # 阅读位置到原页/区域的映射
  quality-report.json         # 完成页、待核对区域、失败项和检查统计
  figure-notes.json           # 独立图解及核对状态，默认不混入教材全文
```

`document.json` 是唯一内容中间结构；HTML 和 MD 由它确定性生成，避免让模型重复生成整本 HTML、MD 和 JSON 浪费 Token 并造成内容不一致。MD 支持相对图片链接、LaTeX 与复杂表格的安全 HTML 回退；不支持表格结构时保留图像并记录原因。

沿用 Markdown 禁止任意 HTML、表格白名单净化和 KaTeX trust=false；新电子书模板脚本由项目提供，不执行模型代码。解包沿用路径穿越、资源哈希、大小与重复条目校验。

需分别验证 StudyHub 内阅读、通过本机服务离线阅读，以及直接打开 HTML 的基础阅读。浏览器 file:// 对 PDF/资源读取可能有限制，不能把需本机服务的对照能力写成“双击 HTML 全功能”。全书在 StudyHub 内的阅读与对照是必达项。

## 7. 阅读与原书对照

“阅读”入口增加电子书/原貌/对照选项，旧文字资料使用原流程。章节目录、阅读位置、字号、行宽、搜索、选区和批注沿用现有 UI 与资料域。

- 原貌视图复用原 PDF，分页加载，支持缩放、跳页和原印刷页定位。PDF 页码始终有效；印刷页未确认时显示未知，不套用一个全书固定偏移。
- 电子书恢复标题、段落、列表、公式、图表和注释，保留页边界锚点；图/表可放大，低质量区域有查看原图入口。
- 并排对照按原页/块映射定位，先实现点击同步，再实现滚动同步。跨页段落、续表以多个区域映射处理，不仅按滚动百分比同步。
- PDF 原页采用同权限的 Range 或有界分块消息桥。是否能注册鉴权 Range 路由由 C06 宿主探针决定；不能使用未鉴权的本地文件服务，也不能把约 198 MB 整书转 base64 塞入旧 40 MiB 通道。
- 长书采用章节/页虚拟化、有限渲染缓存、位图释放和按需裁图；记录冷启动、翻页、内存峰值及磁盘占用。不得预渲染并永久复制全部高清整页作为必要条件。

电子书选区同时保存该阅读版本位置和原页/块证据。普通文字引用仍指向确实存在的文字范围，纯图页不能伪造 source.text；图片继续使用现有 visualCitations。

## 8. 原有出题功能的完整图片接入

复用既有 topicScope/sectionWeights，先匹配主题和章节，再选择正文、相关图注及真实图/表。章节与图像索引要覆盖 image、chart、table、equation，不只覆盖目前图解默认选中的 image/table。

普通批量出题与独立带图入口共用“证据包”：真实文字范围、页/块、图像附件、哈希、裁图信息和必要原页上下文。每道题按预算取 1–4 张有关图，不能把整本教材或全部图片附在每个调用里。

规划、求解、编题、独立审阅四个阶段，以及补题/编辑后重新审阅，都需要传实际图片；仅在规划传图或引用图解文字不算完成接入。无图题继续使用既有文字通道。

质量门禁至少检查主题、教材证据、题干条件充分、唯一答案/评分标准、单位与公式、视觉事实、器件/连接解释、题目重复和学习价值。禁止把无关参考文献识别问题充作 MOS 器件题。生成 30 题需有内容分布规划；不足 30 题时显示通过数量及缺口，而非用无关题补齐或把部分完成显示成全部成功。

对反相器验收集明确核对：上方栅极带圆圈且接 V_DD 的是 PMOS，下方接地的是 NMOS；考察上拉/下拉、移除器件、初始电压、输入状态与输出是否浮空等条件。这个人工核对案例用于验收，不把答案写进所有模型请求来伪装识图能力。复杂电路的模型答案仍可能错误，不能承诺自动全对。

沿用草稿、独立审核记录、编辑失效和事务发布门禁。练习/模拟考试/错题/复习/备份均保留 visualCitations，答题前显示必要原图，不泄露答案或图解。

## 9. 兼容、恢复与预算

旧 documentId/sourceId/revision、题目 ID、作答历史、选区、批注、引用、复习调度和 SM-2 记录均保持。已有文档重解析新增版本，不覆盖旧 source.text；既有 OCR、云端转写、人工修订和模型图解有清楚版本边界。检索只索引选定当前版本，旧题仍可读取绑定的历史资产。

新读写操作在 materials/generation 原权限域内注册契约、端口和集合，不能越权写全库。结构和资源先暂存校验，通过后原子发布；失败重试保留已成功页，正式引用不指向半成品。暂存检查点必须进入明确的备份/恢复契约或明确声明不包含它。

新增云解析任务分阶段记录保存、渲染、识别、精修、整编、导出和核验。“本地渲染失败”“模型权限错误”“待核对”分别呈现，修正当前本地解析也显示“模型调用失败/补题”的错误语义。可暂停/宿主重启恢复需要真实实现、检查点重放和能力声明，不能继承旧任务却假称已支持。

缓存指纹包含原 PDF、页/区域、渲染与坐标变换、provider/model、可取得的模型版本、detail/推理配置、提示词与 Schema、上下文、人工选择与修订。无法取得稳定模型版本时标明限制并允许强制重解析。复用前核验资产。

预算按请求派发前预留输入和最大输出、并发在途调用一起计算；不能沿用仅按已结算量检查的软预算。若宿主能提供可靠上界和结算量，可实施 Token 硬限制；否则只承诺请求次数/图片字节/最大输出等可执行上限，显示 Token 估算及未知用量并停发，不宣称美元绝不超支。取消不抹掉已经发生的厂商费用。解析和后续出题分别记账。

## 10. GPT-6 Luna 整书 Token 与费用估算

**结论：本书首次云端转换可先按约 300 万–800 万 Token 做普通方案预算；更充分的局部精修和图表复核可按约 600 万–1,500 万 Token 留预算。两者是有条件的工程估算，不是实测账单或已确认的 Luna 图像计数。** 建议第一轮开发与验收按约 600 万 Token 的中间场景准备，20–30 页实测后重算，不把这个数设置为保证足够的硬截止值。

统计范围：整本转写、结构 JSON、局部精修、章节整编和有界重试。不包含生成题组、向量索引等后续模型费用；本地 HTML/MD/裁图/打包不消耗推理 Token。

依据与限制：

- 已测 572 页及约 60 万现有 OCR 字符，但 OCR 可能漏识，不能作为全文真值。中文、英文、公式、JSON 的分词密度不同；这里以正文转写和块结构合计约 100 万–250 万输出 Token 估算普通方案。
- 页面图像输入量由模型图像预处理和 detail 决定，不由 PDF 文件 MB 或中文字数决定。当前查到的官方图像计数表没有明确列出 `gpt-6-luna` 的专用换算系数，不能把 Astra 或 5.6 Luna 的系数当作它的已确认规则。[图像输入说明](https://developers.openai.com/api/docs/guides/images-vision)
- 普通方案暂设输入约 200 万–550 万，输出约 100 万–250 万，总计 300 万–800 万。高质量场景暂设输入约 450 万–1,100 万，输出约 150 万–400 万，总计 600 万–1,500 万。范围已经包含局部处理和重试假设；若使用默认高推理、大量全页重复复核或要求模型重复输出整套 HTML/MD，可能超过范围。

可复算中间场景（每项 Token 密度都是待实测的假设）：

```text
逐页输入：572 × (4,000 图像 + 700 提示/上下文) = 2,688,400
局部精修：300 × (2,000 图像 + 500 提示/上下文) =   750,000
章节整编输入                                              180,000
初次输入小计                                            3,618,400
全文/块、局部结果与章节输出合计                           1,230,000
按 20% 重试余量：输入 4,342,080；输出 1,476,000
合计 5,818,080 Token，约 582 万
```

不把当前 321 万字符 manifest 原样要求模型返回：其中资源哈希、资产元数据及程序可计算字段由本地补充；HTML/MD 从 JSON 生成，可显著减少重复输出。

截至 2026-10-11，官方 GPT-6 Luna 标准短上下文价格为每百万输入 $0.10、输出 $0.50。按上述输入/输出场景、不计缓存折扣，普通方案约 **$0.70–$1.80**，较充分精修约 **$1.20–$3.10**；中间场景约 **$1.17**。这些金额假定图像折算后按该输入费率结算、低或关闭推理且输出已含相应开销，不是本机 provider 报价。[GPT-6 Luna 官方模型与价格](https://developers.openai.com/api/docs/models/gpt-6-luna)

第三方转发、不同处理档位、区域价格、隐藏推理和重试可改变账单；单次很长上下文也可能适用更高价格。因此不按整本塞进长上下文、不默认套用 Batch 折扣。具体 route 是否等价官方模型和计费需 C01 确认。

校准办法：从正文、公式、表格、电路、双栏、目录/文献和低质量页分层抽取 20–30 页，固定参数真实调用，记录输入/缓存/输出/推理及重试。按页类型加权外推，并给失败率和精修率情景区间，不能仅选干净论文页。宿主可用时接入官方输入计数能力；不能透传则依靠实际响应 usage，不绕过 DSH 私取密钥。若 usage 不完整，明确不能给精确 Token 结论。[官方 Token 计数说明](https://developers.openai.com/api/docs/guides/token-counting)

## 11. 分阶段实施 C01–C12

每项完成相关验证后再推进依赖项；在现有 `implementation/progress.md` 记录状态、源码提交、测试命令和真实证据，区分合成测试、真实 DSH 调用与人工校对。开发使用独立源码、隔离 DSH profile 和测试库。

### C01：基线与真实模型能力探针

核对安装版本、源代码、既有数据哈希和回归基线；通过 DSH 目录选择真实视觉模型并验证附件、可用配置及 usage。包含扫描正文、PMOS 电路和表格最小样例。通过条件：模型实际收到图并返回可校验内容，路由/用量记录真实；未配置 Luna 则标阻塞该模型验收，不能用别的模型冒称 Luna。

### C02：云端结构契约及旧格式兼容（依赖 C01）

扩展 visual manifest 与阅读映射，冻结 Schema 和新增权限/端口；维护旧版本、原引用和人工修订边界。验证新旧文档/备份往返、错误 JSON/越界坐标/不存在资产拒绝，以及旧资料哈希与引用不变。

### C03：轻量 PDF 分页与坐标转换（依赖 C02）

复用流式上传及原件存储，实现清晰页图/切片、受控临时文件与附件预算；记录旋转、CropBox 和局部变换。验证无文字层、混合 PDF、旋转/裁切页、图中 PMOS 圆圈可读，以及 198 MB 文件不进入旧整件 base64 通道。

### C04：原生云端解析 Job、检查点和预算（依赖 C01–C03）

新增真正的云解析适配器，保留本地入口；接入 gateway、请求前预算预留、限流重试、取消、暂停及重启恢复。验证中途取消/宿主重启后仅续做未完成页；改变模型/提示/渲染参数不误复用；认证失败不无限重试。未实现暂停/恢复前维持 unsupported/none。

### C05：整页/局部识别与图表公式精修（依赖 C04）

实现结构转写、真实资产裁取、候选坐标验证、阅读顺序、图注/子图和跨页表格/段落整理。真实运行分层 20–30 页并人工核对，生成质量报告及 Token 校准。模型仍无法保证准确的块保留原图并标待核对，不伪造正常全文。

### C06：大文件原书阅读与区域定位（依赖 C02–C03）

验证宿主鉴权 Range/分块能力，接入 PDF.js 按需读取，复用预览资源和生命周期管理。真实打开本书首/中/末页、连续翻页及区域定位；跨库/无权限请求拒绝；记录冷启动时间、内存峰值、缓存与位图释放。C01 可并行做此能力探针，但接口在此阶段完成。

### C07：JSON→HTML/MD 资源包（依赖 C05）

增量扩展现有导出与归档，按章生成电子书和完整 MD。校验资产哈希、引用、公式/表格净化、无模型可执行代码；旧 JSON 与新压缩包分别往返验证。StudyHub 内阅读和本机离线服务模式实际验证；直接打开 HTML 的限制如实记录。

### C08：StudyHub 电子书和原页对照（依赖 C06–C07）

接入既有阅读入口、目录、图表放大、搜索、选区、批注、书签/阅读位置和同步定位；旧阅读入口原行为保持。浏览器实际检查教材电路、复杂表格、跨页正文及长章节，窄窗口布局也通过；不能仅用静态 HTML 截图充作应用内验收。

### C09：检索与普通批量带图出题（依赖 C05、C08）

在现有选材、覆盖计划和草稿管线接入统一图文证据包；规划/求解/编题/审阅/补题实际传图。验证纯文字旧路径、图像额度、无视觉路由、证据不足拒绝与主题不偏离；真实 MOS 30 题验收，记录接受、拒绝及未补齐数量和每题证据。

### C10：练习、历史、发布和备份兼容（依赖 C07、C09）

验证题目编辑后复审、事务发布、各题型/考试/错题/复习原图显示、旧答案和 SM-2 不变；旧题继续定位历史资料。隔离库执行旧 JSON、新资源归档及备份恢复，逐文件 SHA 与完整 Store 对比；不在正式库做破坏性回退验证。

### C11：572 页全书真实转换与质量验收（依赖 C05–C10）

按小样本校准后的配置运行整书，记录全书第一次无缓存耗时/用量与后续缓存复用，不能将旧约 6 秒缓存导入成绩当作首次 OCR 性能。核验 572 页状态、全部原资产、章节/图表/公式映射，分层人工抽检；对缺页/未识别正文不标全书完整。实测整书阅读、原书对照及图像辅助出题。

### C12：构建、交付与可验证回退（依赖 C11）

运行相关回归、lint/build/release 校验；必要时跑完整套件，列出基线失败与新增失败。生成定制安装包、使用说明、实际测试/用量报告和回退步骤。通过 Desktop 官方 generation 安装机制在隔离环境验证升级，不能使用曾破坏 Desktop 投影的普通 CLI 安装流程。正式环境安装作为单独后续步骤，本轮计划交付不替换正在运行的版本。

## 12. 验收门槛、交付与继续位置

以下是后续开发的验收目标，并非本轮已经达成的成绩：

- **完整性硬门槛**：572/572 原页记录；原 PDF 哈希不变；已发布资源 100% 可读且哈希有效；无失效资产/映射、静默漏页、未披露正文缺失。空白页也保留原页号。
- **抽检质量目标**：先建立至少 10,000 字符、30 个图/表/公式区域的人工校对集，覆盖难页与随机保留页；正文字符准确率目标 ≥99%，阅读顺序正确率 ≥98%，图区域/图注对应正确率 ≥95%。每个统计明确分母和错误定义，合并单元格、负号、上下标、器件类型等关键项单独报告。达不到时局部精修或原图回退，不修改阈值伪装通过。
- **电路与题组门槛**：反相器关键器件、节点、输入条件与输出解释人工对图核对；真实 MOS 题组不得混入无关参考文献题。30 题只有通过逐题审阅才显示 30/30；待核对图像不能成为已核对证据。独立模型审阅不代替人工抽检，也不保证任意新题永远正确。
- **兼容硬门槛**：预选旧库的资料、引用、批注、题目/答案与调度快照不变；新旧备份恢复一致；相关基线测试不新增失败。历史 9 项失败保留原因/结果，不写“全量全通过”。
- **性能验收**：报告所用机器、无缓存解析总时间/费用、缓存复用时间、阅读首屏/翻页延迟、解析及阅读内存峰值和磁盘增长；优化目标由 C05/C06 真测冻结，当前不编造秒数。

交付物为定制安装包、按章 HTML/MD/JSON 资源包（用户教材内容留本机）、真实验证报告、使用说明和回退步骤。回退顺序：停止相关任务 → 导出并核验现库与资产备份 → Desktop 官方安装机制切回保存的旧包 → 打开升级前备份或旧库副本 → 核对旧引用与复习记录；旧程序不理解新格式时保留新库独立副本，不让它覆盖新版本数据。

当前最合理的开发入口是 **C01–C03**，先证明真实 DSH 模型与轻量分页能够识别难页，再开展整书管线；不优先购买本地 GPU，也不先重写全部阅读/题库模块。

本轮只读证据：`implementation/evidence/cloud-pdf-plan-native.json`、`cloud-pdf-plan-book.json`、`cloud-pdf-plan-structure.json`。证据仅含版本、哈希、计数、抽查结论与估算假设；没有教材图片、全文或凭据。本计划完成不等于 C01–C12 功能完成。
